# 대화형 프로젝트 선택·등록·생성 설계

사용자의 2026-09-07 요청에 따라 정확한 프로젝트명 없는 자연어 작업을 Slack, Telegram, 터미널 공통 대화로 처리한다. 기존 “모두 진행” 승인에 따라 구현과 설치 검증까지 진행한다. 코드와 문서는 미커밋 상태로 유지한다.

## 구조

도구 없는 Codex 구독 인증 추론이 프로젝트 메타데이터와 짧은 대화 기록을 받아 구조화된 의도를 제안한다. 서버는 실제 catalog ID를 검증하고 후보가 애매하면 번호 선택을 묻는다. 현재 선택한 프로젝트를 세션에 저장하고 실제 실행은 기존 native Orca relay로 전달한다. AI는 직접 shell/파일/네트워크/등록을 실행하지 않는다.

대화별 영속 상태는 선택 프로젝트, 최근 작업 ID, 제한된 대화 기록, 대기 중 후보 및 등록/생성 제안이다. Slack 사용자+채널+스레드, Telegram 사용자+대화, 터미널 sessionId로 분리한다. 서비스 재시작 후에도 번호 선택과 확인 대화를 이어간다. 기존 durable receipt로 재전송 중복 실행을 방지한다.

## 대화

기존 프로젝트는 이름/별칭/경로와 사용자의 설명으로 찾는다. 여러 후보 또는 추측 후보는 번호와 이름/경로로 묻고 선택 전에 실행하지 않는다. 질문/진행 조회/작업 지시를 구분한다. 선택 이후 프로젝트명을 생략할 수 있다. 바꾸기/취소/새 대화를 지원한다.

없으면 기존 폴더 위치 단서를 묻는다. 사용자가 지정한 디렉터리 범위에서 제한된 깊이와 항목 수로 폴더명 및 .git 존재만 탐색한다. 비밀 파일·프로젝트 소스·보호 파일 내용을 읽지 않는다. 검색 결과는 실제 경로만 제시하고 없다는 단정 대신 탐색 범위를 알린다. 등록 전 경로를 보여주고 확인한다.

새 프로젝트는 목적/이름/정확한 생성 위치를 논의한다. 최종 경로와 요청을 보여주고 확인 후 없는 디렉터리에만 초기 Git 저장소를 생성해 Orca에 등록한다. 기존 폴더 덮어쓰기와 임의 삭제는 금지한다. 실제 스캐폴딩과 개발은 등록 뒤 별도 사용자 지시를 Orca로 전달한다. 초기 빈 커밋은 새 저장소에 한해 worktree 사용에 필요한 초기화 사실을 미리 설명한다.

## 터미널

hq chat [--session ID]는 반복 입출력 대화 모드다. hq ask [--session ID] <문장>은 동일 대화를 단발 명령으로 이어간다. chat 새 세션은 고유 ID를 표시해 재개 가능하게 한다. /exit 또는 EOF로 종료, /new로 새 대화. 클라이언트 대기는 AI 해석 예산을 수용하되 유한하다.

## 검증

AI 경계는 fake 결과를 주입해 의도 검증/잘못된 ID/애매한 후보/취소/세션 분리/재시작/등록·생성 확인 전 부작용 없음/중복 전달을 검사한다. 파일시스템 경계는 실제 임시 디렉터리와 Git 저장소로 제한 탐색·기존 경로 보호를 확인한다. 터미널은 스트림 또는 CLI 프로세스로 다회 대화를 검사한다. 실제 Codex 추론, 설치본 터미널 대화, 개인 Slack의 모호한 프로젝트 후보 왕복으로 검증한다. Telegram 실제 입력은 사용자에게 남아 있는 요청이 있으므로 검증 결과를 구분한다.
