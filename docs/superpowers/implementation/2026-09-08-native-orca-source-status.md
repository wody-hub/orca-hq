## Material behavioral gaps

- **Native-first route:** Tool-free classification is implemented, but its execution target is a model conversation. Project analysis can finish without a worker. `apps/gateway/src/managed-runtime.ts:187` gives the execution conversation tools, while `:216` creates the separate tool-free router; `:228` wires substantive work back to the conversation.
- **Admission unit and atomicity:** Context slots are occupied before resource acquisition (`apps/gateway/src/context-executor.ts:41`; `apps/gateway/src/progress-runtime.ts:420`). Thus whole-resource acquisition is atomic, but capacity plus resources is not. There is no safe-integer/unlimited validation or lower-limit restart behavior; the strict config schemas cited above would reject the new field.
- **Cleanup accounting:** `apps/gateway/src/orca-relay.ts:514` records release_pending/release_unknown only as warnings while the job can remain succeeded. `apps/gateway/src/context-executor.ts:84` releases native occupancy on succeeded/failed/stopped alone. This does not satisfy retaining capacity until release is proven or retained-idle is explicit.
- **Models and reusable terminals:** No `--model`, `--effort`, `--terminal` launch branch or `worker-retain` call exists in the relay. Completed followup creates a new Task in the prior checkout (`apps/gateway/src/orca-relay.ts:858`), then uses the fresh Codex launch path (`:618`); it does not reacquire an explicitly retained primary terminal. Active guidance is sent to the exact Dispatch (`:836`), but local `observed` means send completion (`:846`), not worker read/processing confirmation.
- **Coordinator/recovery:** Existing generation fences are per context, not persisted gateway ownership epochs. Current relay request records preserve HQ request IDs/phases but omit Orca mutation request IDs (`apps/gateway/src/orca-relay.ts:64`), and the call builder has no original-request retry/query protocol (`:289`). No durable fanout DAG, planner settlement-before-children, question delivery journal or acknowledgement sequencing exists.
- **Truthful status/channel identity:** Context state becomes running and emits agent.started before execution (`apps/gateway/src/progress-runtime.ts:386`, `:396`, `:440`). Execution input hardcodes `source: "terminal"` / `userId: "local"` (`:444`), and control dispatch does likewise (`apps/gateway/src/managed-runtime.ts:244`). Native `updated_at` is copied into job.updatedAt (`apps/gateway/src/orca-relay.ts:474`) without a separate receipt observation timestamp in NativeJob (`:33`).
